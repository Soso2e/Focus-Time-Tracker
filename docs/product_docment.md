本制作における**最終成果物**を以下に明示する。

#### 成果物1：デスクトップアプリ（Mac / Windows）

* 常駐型の集中時間トラッキングアプリ

* 集計データのみを用いた共有
* フレンド全体ランキング / 招待制グループ
* 健康的な競争・共同目標の実現

## 1. 企画概要

**目的**：Mac / Windows で「いまアクティブなアプリ（＋必要ならウィンドウタイトル）」を自動取得し、作業時間を計測・可視化する。さらに、友人・グループと共有して“健全に”切磋琢磨できる体験を提供する。

**プロダクトの核（One-liner）**：

> **クリエイターの「集中の質」を可視化し、努力がちゃんと報われる時間トラッカー**

**設計原則**：

* **自動 × 納得感**：自動計測を信頼でき、あとから修正できる
* **ローカルファースト**：生ログは端末外へ出さない
* **健康的な競争**：長時間労働を助長しない多面的スコア
* **邪魔しない**：軽量・バックグラウンド常駐

## 2. 既存プロダクトとの差別化の方向性

既存の自動タイムトラッカーは存在する（例：ローカル保存/OSS、サブスク型、mac専用など）。
本企画は「**競い方**」と「**クリエイター向けの分類**」に寄せて差別化する。

差別化アイデア：

* “アプリ名”ではなく **カテゴリ** でログをまとめる（例：Maya=「3D制作」）
* **集中ブースト**：一定時間連続で同カテゴリにいると“集中セッション”として自動認定
* **共有はカテゴリ集計だけ**（ウィンドウタイトルやURLは共有しない）
* **フレンド戦**：週単位の「ベスト集中時間」「休憩の上手さ」「切替の少なさ」など、多面的スコア

## 3. ターゲット / ユースケース

### 想定ユーザー

* クリエイター（3D制作、映像制作、ゲーム開発、プログラミング、資料作成など）
* 学生・自主制作勢
* 在宅/PC中心の作業者

### ユースケース

* 「Maya/AE/Unity/VSCode」を何時間使ってるか知りたい
* 今日は“制作”に何時間、”SNS/動画”に何時間吸われたか見たい
* **調べ物が多い**ので、ブラウザに移っても“集中が途切れにくい”判定が欲しい
* 友達と「今日/週/月の集中」を競ってモチベ上げたい

## 4. 主要機能（MVP→拡張）

## 4.1 MVP（まず作る最小構成）

1. **アクティブアプリ監視**

* 1〜5秒間隔でポーリング
* アプリ名 / プロセス / （任意）ウィンドウタイトル を取得
* タイムラインとして記録

2. **Glue（隙間時間の自動結合）**

* 制作系カテゴリ→短時間のBrowser遷移を“制作の一部”として自動マージ
* 許容時間は設定可能（デフォルト3分）

3. **AFK/作業継続判定（スマートAFK）**

* 入力なし＝AFK
* ただし高負荷（レンダリング/書き出し）時は「作業継続」と判定

4. **カテゴリ分類（手動＋ルール）**

* アプリ名→カテゴリのマッピング
* 未分類/Browser時間は後から修正可能

5. **事後タグ付けUI**

* タイムライン上でドラッグ＆ドロップして一括上書き

6. **集中セッション（デフォ10分）**

* 10分以上継続で1本
* Glue許容内のBrowserは継続扱い

7. **可視化ダッシュボード**

* 今日/今週/今月
* カテゴリ別・セッション別

8. **データ保存/エクスポート**

* SQLite（ローカル）
* CSV/JSON

## 4.2 拡張（競争・共有）

9. **共有レベル切替（オプトイン）**

* Lv0：共有しない
* Lv1：カテゴリ集計のみ（初期推奨）
* Lv2：アプリ名＋カテゴリ
* ウィンドウタイトル/URL/ファイル名は常に共有対象外

10. **ポモドーロ連動（宣言モード）**

* 手動で「今から集中」を宣言
* 自動記録と一致した場合、集中ボーナス付与

11. **フレンド/グループ**

* フレンド全体（総当たり）
* 招待制グループ（内輪機能）

12. **多面的メトリクス**

* 集中セッション数 / 深い集中率 / 切替回数
* 休憩の達人 / AFK率
* 総時間は任意表示

13. **ギルド（グループ）目標**

* 共同目標・週次チャレンジ

# 付録：集中セッション（デフォルト10分）と“調べ物”の扱い

## 集中セッション定義（デフォルト）

* **10分以上**同一カテゴリ（または許容ルール内）に滞在 → **集中セッション1本**
* 10分未満で途切れた場合は「中断」として別カウント（改善指標）
* しきい値はユーザーが変更可能（10/15/25/45分など）

## “調べ物”で集中が途切れないための設計（超重要）

クリエイターは制作中にブラウザへ頻繁に移動するため、集中判定に「許容」を入れる。

**案：ブラウザ許容ルール（デフォルトON）**

* 直前カテゴリが「制作系（3D/映像/開発/コーディング）」の場合、

  * Browser が **連続◯分以内（例：3分）**なら “制作の一部” とみなして集中を継続
  * それ以上なら「調べ物」カテゴリとして独立計測

**案：ドメイン/キーワードの安全運用**

* URLやタイトルは基本保存しない（プライバシー）
* もし将来使うなら、ローカルでのみ「学習」し、共有には絶対出さない

# 付録：共有・競争の設計（グループ中心）

## 共有単位

* **全フレンド公開（Friends）**：全ての友達と同じランキングで競う
* **グループ（Group）**：招待制の内輪コミュニティ

## 期間軸

* **日次 / 週次 / 月次** の切替

## グループの“内輪機能”アイデア

* グループ内チャレンジ（例：今週は制作20h、集中セッション30本）
* チャンネル別スコア（制作だけ、休憩も含む、などグループでルール固定）
* 罰ゲームではなく“ご褒美”設計（達成時に称号/スタンプ）
* 週報の自動生成（グループ内だけで共有）
* 共同目標（みんなで合計100セッション達成など）

## 招待方式

* 招待リンク / 招待コード（期限付き）
* 管理者権限（メンバー追加・ランキング軸の固定・公開範囲）

※重要：どの共有レベルでも「ウィンドウタイトル/ファイル名/URL」は共有しない
